### English

- The `zcode` channel now ships both services the desktop client signs in to, as two regions: `zai` (Z.ai — `api.z.ai`, the client's default) and `bigmodel` (BigModel — `open.bigmodel.cn`). New accounts default to `zai`. The two realms have different authorize hosts, callback schemes and API bases, so a credential is only ever sent to the service it was minted for.
- Add browser login for zcode accounts. The console opens the authorize page of the account's region and the operator pastes the callback URL back — neither realm can redirect into this process, so pasting is the flow rather than a fallback. For Z.ai the console asks for the ZCode CLI's registered loopback (`http://127.0.0.1:9999/callback`) instead of the `zcode://zai-auth/callback` custom scheme: a custom scheme is claimed by whichever desktop app registered it (an account manager, say), which swallows the code and leaves the address bar with nothing to copy, while the loopback keeps the whole callback in the browser. BigModel uses its registered `zcode://oauth/callback`. Any registered callback of the realm is accepted on paste, and the redirect the browser actually used is echoed to the token endpoint. The pasted code is exchanged at `https://zcode.z.ai/api/v1/oauth/token`; for Z.ai the returned access token is then exchanged at `https://api.z.ai/api/auth/z/login` for the ZCode JWT the chat path uses, while BigModel returns that JWT directly. Account identity (email, user id) is filled best-effort from the realm's userinfo endpoint.
- The login round is bound to a 32-byte `state` minted per start and expires after 15 minutes, so a callback link from an earlier round cannot complete a newer one; the pasted URL is validated (scheme, the callback hosts of that region, `code`/`authCode`, provider `error`) before any exchange happens, and a rejected exchange leaves the account untouched. Pasting an API key is exposed as the PAT login method alongside it.

### 中文

- `zcode` 渠道现在同时提供官方桌面客户端登录的两个服务，各占一个区域：`zai`（Z.ai——`api.z.ai`，客户端默认）与 `bigmodel`（BigModel——`open.bigmodel.cn`）。新建账号默认 `zai`。两个服务的授权域名、回调协议与 API 地址都不同，因此凭证只会被发到它所属的那个服务。
- 新增 zcode 浏览器授权登录。控制台打开该账号所属区域的授权页，用户把浏览器跳转后的回调链接粘回来——两个服务都无法把回调打到本服务上，所以「粘贴」就是完整流程而不是兜底。Z.ai 区域要的是 ZCode CLI 注册的**本机回调** `http://127.0.0.1:9999/callback`，而不是 `zcode://zai-auth/callback` 自定义协议：自定义协议会被机器上注册了该协议的桌面软件（比如账号管理器）抢走，code 被它吃掉、地址栏什么都不剩；本机回调则把整条链接留在浏览器里。BigModel 区域用官方注册的 `zcode://oauth/callback`。粘贴时该区域注册过的任一回调都接受，换取 token 时回显浏览器实际用的那一个。粘贴的 code 会去 `https://zcode.z.ai/api/v1/oauth/token` 换取 token；Z.ai 还会用换到的 access token 再到 `https://api.z.ai/api/auth/z/login` 换取对话路径使用的 ZCode JWT，BigModel 则直接返回该 JWT。账号身份（邮箱、用户 ID）尽力从对应区域的 userinfo 接口补齐。
- 每次登录都会新生成 32 字节 `state` 且 15 分钟后过期，因此上一轮的回调链接无法完成新一轮登录；粘贴的链接在真正换取 token 之前会先校验（协议、该区域允许的回调 host、`code`/`authCode`、上游 `error` 参数），换取失败不会污染账号。同时把「粘贴 API Key」作为 PAT 登录方式一起开放。
