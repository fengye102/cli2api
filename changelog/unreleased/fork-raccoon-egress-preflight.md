- raccoon: a browser login on this deployment only works over an egress — the site refuses this server's own address, and every raccoon account here carries `socks5://ag-egress-socks:17890` — but nothing said so. Starting a round on an account without a proxy handed out an authorize URL that was doomed: the operator finished it, pasted the `127.0.0.1` callback, and then the code exchange sat on a thirty-second timeout before failing with "context deadline exceeded", which reads like the login hanging rather than a missing setting. A round with no proxy now pre-flights the dial (four seconds) before it hands out a URL, and the paste re-checks it, so the answer arrives immediately and names the cause: the site only accepts a proxy egress, the account has neither `proxy_url` nor a global proxy, and the message includes the egress this deployment already uses when one is configured. A round that has a proxy pays nothing — the proxy does the talking — and a successful check is cached for two minutes while a failure never is, so fixing the setting takes effect on the next attempt. The loopback test servers and local relays this provider also talks to are exempt.
